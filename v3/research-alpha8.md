# Alpha 8 — research and review evidence

## Architecture
Microsoft documents WebView2's browser/renderer/GPU/utility process architecture. It is not an accidental multiple-instance bug. Disabling its sandbox or killing child processes is not a fix. Slint, egui and direct Win32 were considered; only windows-sys is cached and built in this pass. An isolated Win32 proof uses the same Rust core, native tray icon, URL/preset/conditional playlist, queue toggle and separate state. Actual screenshot shows dated controls; do not replace the more complete frontend until native visual and functional parity. Idle child tree measurement is a feasibility result, not an equal-feature benchmark. https://learn.microsoft.com/microsoft-edge/webview2/concepts/process-model ; https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backends_and_renderers/

## Download integrity
Original Python process_owner.py and media_tools.py identified two migration gaps: child process ownership and pinned first-use installation. Windows Job Objects now supervise yt-dlp/FFmpeg long-running children; closing guard terminates owned processes, assignment immediately after spawn (remaining race acknowledged). Scoped Original single-job pause uses deterministic job-owned stage, UUID marker, reparse checks and safe partial validation. No completed manifest reused. Controlled pause and restart preserves same job identity; exact nonzero Range request and byte-equal valid MP4 tested. Other formats, playlist, processing and arbitrary crash resume not certified. No auto restart from incomplete publications. https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects ; https://github.com/yt-dlp/yt-dlp
